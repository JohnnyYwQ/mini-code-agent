# Separate User and Space Memory scopes

Memories use two ownership scopes: User Memory is available across all of one User's Memory Spaces, while Space Memory is available only within one trusted Memory Space. Each Conversation belongs to exactly one Memory Space; a Space may contain several Conversations for shared context or one Conversation for isolated context.

Every add and search operation receives a trusted Memory Context containing both the current User and Space; Memory consumes these identifiers but never creates, switches, or authorizes Spaces. Chat/Application resolves the request's Conversation using the trusted local User, verifies ownership, derives its Memory Space, and constructs the Memory Context before calling either the Agent Runtime or Memory; if resolution or ownership fails, neither downstream module is called.

One add operation invokes extraction once, and each extracted Memory is classified as User or Space Memory. The model may choose only that classification: Memory copies the trusted User and, for Space Memory, the trusted Space into storage, so model output can never select an identity or widen the eligible Scopes. The extraction instructions require ambiguous classifications to be emitted explicitly as Space rather than risk exposing temporary context across Spaces; a missing or invalid classification is a protocol failure, never silently defaulted by parsing. A successful extraction may return no Memories. Extraction validates the complete model result before returning it; if any proposed Memory has invalid text or classification, the whole extraction fails and add performs no writes.

User Memory omits `space_id`, while Space Memory includes it; no separate scope-type value is stored because it would duplicate derivable state. Search and the extractor's semantic comparison combine the current User's User Memory with the current Space's Space Memory. Each relevant existing Memory is presented to extraction with its User-or-Space classification, but without User or Space identifiers, so the model has the semantics needed for deduplication without control over ownership.

Hash deduplication is only a final exact-match guard inside the selected target Scope: User Memory is checked only against User Memory, while Space Memory is checked only against the current Space's Memory. Search hides exact duplicate Source Text across the two visible Scopes without deleting stored Memories; when a User and Space Memory have identical Source Text, the User Memory is returned and the Space copy is omitted before applying the result limit.
