# Use native uv for CUDA retrieval evaluation

CUDA Retrieval Evaluation Runs use a dedicated uv-managed Python environment directly on the pinned Linux host, reusing its NVIDIA driver and configured download proxy. The ordinary CPU development group and the `cuda-eval` optional extra are declared as conflicting selections in the repository's single `pyproject.toml` and `uv.lock`; using an extra lets uv select the cu124 PyTorch index only for CUDA evaluation without making the Linux-only wheel the source for ordinary macOS development. The runner reconciles an existing dedicated environment in place with `uv sync --frozen --no-default-groups --extra cuda-eval` instead of rebuilding it, resolving open project requirements, or maintaining a second requirements lock. `--no-default-groups` excludes the CPU and development groups while the extra retains the project and its runtime dependencies. Already valid packages and content-addressed model caches are reused, while the lock remains the authority for the final environment. Docker and NVIDIA Container Toolkit are deliberately excluded: on this single host, a native environment reduces disk usage and operational setup while reproducibility comes from pinned dependencies, explicit preflight checks, and recorded run metadata; portability and container isolation are not goals.
