# Require CUDA for dense encoding and reranking

A CUDA Retrieval Evaluation Run binds both the E5 dense encoder and BGE reranker to `cuda:0`, uses FP16 for BGE on the pinned RTX 2070-class GPU, and fails if either model's compute-heavy operators fall back to CPU. ONNX Runtime may still assign shape and control operators to its implicit CPU execution provider because that is part of CUDA graph partitioning rather than a whole-model fallback; the E5 preflight therefore profiles a real embedding, requires compute-heavy CUDA operators, rejects compute-heavy CPU operators, records both provider assignments, and disables Python's run-level provider retry. This prevents a nominally CUDA run from spending its dominant indexing phase on CPU while remaining compatible with ONNX Runtime's intended CUDA execution model.
