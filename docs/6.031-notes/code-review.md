### Code Review
## object
- Easy To Understand（ETU）
- Safe From Bug（SFB）
- Ready For Change（RFC）

## 好代码的特点
- Dont Repeat Yourself（DRY）
    - RFC，当需要改的时候多出重复需要同步，不变修改

- 需要的地方写注释
    - ETU， 帮助读者理解代码

- 不要魔法变量
    - ETU， 当有魔法变量的时候读者不知道什么意思，代码不好读

- 使用好的命名
    - ETU，读者好理解 

- 用空格帮助读者
    - ETU，读者好理解

- 快速失败
    - SFB，异常情况快速抛错，不要悄悄吧错误返回传播出去

- 不要全局变量
    - SFB， 全局变量最好const固定住，不然运行过程中不知到到底改成啥了

- 应该返回结果而不是打印结果
    - 就应该返回

- 变量只承担一个用途
    - SFB， 变量承担多个用途会很乱，后续不知道当前变量是在干嘛

- 避免特殊情况代码
    - SFB， 特殊情况代码经常容易出错，优先检查通常情况是否包含了特殊情况，往往是包含的
